## Scope and Constraints

- Follow `specs/013-add-chatbot/spec.md`, `specs/013-add-chatbot/plan.md`, and `specs/013-add-chatbot/tasks.md`.
- Approved decisions: Core owns PostgreSQL conversation persistence; use Ollama `deepseek-r1:8b`; limit messages to 2,000 characters, context to 10 prior turns, and chatbot requests to 10 per minute per session; approved knowledge is curated and reviewed in the BFF repository before ingestion.
- Anonymous browser requests carry only the opaque `chat_session` cookie to the BFF. For each anonymous internal Core call, the BFF signs a fresh 60-second HMAC-SHA256 assertion in `X-Chat-Assertion`, with `iss=bgg-shop-bff`, `aud=bgg-shop-core`, `sub=sha256(chat_session)`, `scope=chat:conversations`, `iat`, `exp=iat+60s`, `alg=HS256`, and `typ=chat-assertion`. Core validates the assertion and derives ownership only from validated `sub`; registered bearer auth remains authoritative when present.
- Use a dedicated `CHAT_ASSERTION_SECRET` environment setting; never reuse JWT `SECRET_KEY` or `OPKEY_INTERNAL_SECRET` and never record secret values. Key rotation is a coordinated BFF/Core environment replacement. The assertion is scoped and short-lived but is not one-time and does not promise replay prevention. The assertion and owner ID are not browser payloads, GraphQL arguments, or browser-visible response data.
- Define and structurally validate BFF/Core contracts before implementing behavior; use existing Core catalog operations unless investigation proves a contract gap.
- Accept English and Spanish questions across FAQ, guardrail refusal/clarification/fallback, and catalog-recommendation paths. User-facing assistant text must match the question language; this semantic requirement adds no API fields or routes and does not relax privacy, scope, ownership, grounding, or no-fabrication behavior.
- Keep Core as the owner of persistence and owner enforcement. The BFF signs the approved anonymous assertion and delegates; it owns neither storage nor retention. Run the Core management-command retention runner locally when validating physical cleanup; no periodic schedule was found.
- Keep personal/order details out of retrieval, model calls, Core, persistence, and responses. Never trust a caller-provided owner ID.
- Use only local verification, disposable databases, synthetic test data, and local model substitutes. No staging, production, remote validation, deployment, CI, pushes, or PRs. The user authorized scoped local commits if needed after verification.
- The latest task adds a Chroma metadata-filter fix and a real local Chroma regression; the approved 30-day inactivity-retention requirement is unchanged.
- Preserve unrelated existing dirty files, including `.github/copilot-instructions.md`, `.specify/feature.json`, `CasosDeUso.md`, `bgg-shop.code-workspace`, and root scratch/test artifacts.
- Verified branches: root, Core, BFF, and Frontend are all on local `013-add-chatbot`; preserve all pre-existing root changes.
